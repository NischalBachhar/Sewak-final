# Free-tier operation

Production uses a Worker with static assets, two D1 databases and D1-backed password/session authentication. Isolated staging has its own two databases. A private SQLite-backed Durable Object performs scrypt without storing auth state. No R2, Images, paid transformation, queue or external paid storage is configured. Do not automatically upgrade when quotas are reached. Free quota failures are availability failures; API errors are recoverable 503s where possible.

Cloudflare documents Workers Free at 100,000 requests/day and 10 ms CPU; D1 Free at 5 million rows read/day, 100,000 rows written/day, 5 GB account storage and 500 MB/database. D1 permits 50 queries per Free invocation and 100 bound parameters/statement. Account budgets are shared with other apps. Recheck [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) and [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) before release. The owner confirmed Workers Free on 2026-09-22; billing API reads remain denied, so provisioning records operator attestation. No billing plan was changed. Config cannot convert a paid account to Free.

Lists select explicit model columns, enforce server-side tenant scope and filter/sort allowlists, and use 1–50-record keyset pages. Legacy complete-list views stop visibly at 1,000 instead of silently truncating totals. Booking owner/status/ID indexes and SQL aggregates cover actual UI queries; completed count/revenue/earnings share one query. Public projections derive from current safe records; historical copies exist only for reconciliation. Verified ratings derive from real reviews.

Authorization reads are cached per request and version-guarded inside atomic structured-write batches. Operation/parameter budgets prevent oversized work. Bookings/care/receipts refresh on local mutation, focus/reconnect and a visible-page 60-second timer; hidden pages stop polling. This replaces Firestore push latency with bounded HTTP. Main lists never retrieve BLOBs. Image visibility/metadata precedes digest cache lookup; only an actual image body reads its BLOB. Browser/offline encoding avoids Worker transformation CPU. No signing key or external Auth-admin token exists in the runtime. Password CPU work runs in a stateless Durable Object, leaving the Free HTTP Worker budget for routing and D1 access.

The reconciled remote databases use **393,216 main bytes** and **36,864 media bytes** per D1 metadata, including migration journal overhead. Initial local values were 380,928 and 24,576 bytes. Zero images means no measured average or additional-image estimate (report returns null). An illustrative conservative 500,000,000-byte media budget with 20% headroom and 100,000-byte photos allows about 3,999 photos; at 200 KB approximately half. This is planning, not measured capacity: metadata, indexes and fragmentation consume space. Replacement retains one owner row.

Polling, broad admin scans, public scraping, rating aggregates and simultaneous image views can exhaust Free limits even with little storage. Monitor request/CPU/rows-read/rows-written metrics; narrow filters/pagination before increasing scale. Remote authentication and controlled write smoke passed on Workers Free; sustained load/quota-exhaustion testing has not been performed. Password hashing consumes Durable Object compute quota. D1 rate limits bound abusive attempts, and quota failures fail closed. No paid plan, phone/SMS or billable external auth provider is added. Legacy Functions are not deployed/invoked by this app. Existing unrelated bills are unchanged.
